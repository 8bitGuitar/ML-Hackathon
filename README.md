# PathSnap: GPS map-matching

Given a noisy GPS trip and a road network, PathSnap predicts which road segment (directed arc) the car was on at
every fix and reconstructs the driven route.

**Method:** for each GPS fix, candidate arcs within 50 m are generated and described by 13 features. A tuned
HistGradientBoosting classifier scores each candidate. An HMM decoded with Viterbi then picks one connected route.
A FastAPI backend serves this for unseen trips and a browser UI shows the result on a map.

## Results (10 held-out `student_test` trips)

| Stage | Top-1, reliable fixes | Macro F1 | Route continuity | Route F1 |
|---|---|---|---|---|
| Nearest-road baseline | 55.4% | 0.376 | 0.940 | n/a |
| Best single classifiers (MLP, Random Forest, HGB) | 88.6–88.8% | 0.755–0.772 | 0.969–0.978 | n/a |
| **Tuned HGB + HMM/Viterbi (final)** | **94.5%** | **0.929** | **0.9994** | **0.981** |

Full tables are in `results/comparison/` and `results/hmm/`.

## Repository layout

| `deployment/` | `config.py` (API address, port, data paths), `requirements.txt`, `run_api.sh`, `run_ui.sh` |

Each of `api/` and `ui/` has its own README with details.

## Install

Tested with Python 3.14.

```
python -m venv .venv
source .venv/bin/activate
pip install -r deployment/requirements.txt
pip install jupyterlab        # only to open the notebooks
```

## Data

The raw data (`Student folder/` with `train/` and `student_test/`) is not committed. Place it in the repository
root, or next to it, so that `Student folder/student_test/<trip>/<trip>.track` exists. The API finds it in either
place, or set `PATHSNAP_EVAL_DIR`.

## Run the API and UI (the evaluation demo)

The trained model is committed (`results/final_model/`), so nothing needs retraining.

**Laptop 1 (API)**
```
python api/api.py            # or: deployment/run_api.sh
```
It listens on `0.0.0.0:8000` and prints one log entry per request. Each prediction logs a JSON block with the trip ID,
fix and candidate counts, time for candidate generation, classifier and HMM, and the accuracy.

**Laptop 2 (UI)**
```
deployment/run_ui.sh         # serves ui/ on http://localhost:8080
```
Open `http://localhost:8080/?api=http://<laptop 1 IP>:8000`, pick a trip and press Run. The address can also be set in
`ui/config.js` or typed into the page.

**Two-laptop setup**
1. Put both laptops on the same network. Venue Wi-Fi sometimes blocks device-to-device traffic, so a phone hotspot is
   a safe fallback.
2. On laptop 1, find its IP with `ip -4 addr` and allow port 8000 through its firewall if one is running.
3. From laptop 2, check `curl http://<laptop 1 IP>:8000/health`. It should return `{"status":"ok"}`.
4. Laptop 2 needs only the `ui/` folder and a browser. The map background loads from CARTO (OpenStreetMap data), so it needs
   internet; the route and GPS points draw without it.

The true route never leaves laptop 1: the API returns only the predicted route, the GPS track and the scores.

Settings (environment variables): `PATHSNAP_API_HOST`, `PATHSNAP_API_PORT`, `PATHSNAP_API_URL`, `PATHSNAP_EVAL_DIR`,
`PATHSNAP_MODEL_DIR`. Defaults are in `deployment/config.py`.

## Reproduce the whole pipeline

Run the notebooks in this order, each from its own folder (they use paths relative to the repository root):

1. `data_processing/data_cleaning.ipynb` (or `python data_processing/clean.py "Student folder" data_clean`)
2. `feature_engineering/feature_engineering.ipynb`
3. `model_training/01_…06_*.ipynb` (one per model)
4. `bayesian_optimisation/bayesian_optimisation.ipynb`
5. `model_evaluation/model_comparison.ipynb`
6. `hmm_viterbi/hmm_viterbi.ipynb`

Visualisations: `python visualisations/visualize_trip.py <trip id> --html map.html` draws one trip, and the HMM notebook
writes route maps to `results/hmm/maps/`.

## How to use each part

| Part | How to use it |
|---|---|
| **Inspect or clean raw data** (`data_processing/`) | `python data_processing/analyze.py "Student folder" out` writes trip statistics. `python data_processing/clean.py "Student folder" data_clean` runs the cleaning rules and writes `data_clean/`. Or run `data_cleaning.ipynb`, which explains each rule. |
| **Build features** (`feature_engineering/`) | Run `feature_engineering.ipynb` after cleaning. It writes the per-trip candidate tables to `data_features/` and the selected feature list to `data_features/selection_results.json`, which every model reads. |
| **Train a model** (`model_training/`) | Open one notebook, for example `04_random_forest.ipynb`, and run all cells. It cross-validates by trip, fits on all training trips, scores `student_test`, and saves to `results/<model>/`. `pathsnap_common.py` holds the code all six share, so the models are scored identically. |
| **Tune with Bayesian optimisation** (`bayesian_optimisation/`) | Run `bayesian_optimisation.ipynb`. The Optuna study is saved in `results/bayes_opt/study.db` and every trial in `results/bayes_opt/trials.csv`. |
| **Compare models** (`model_evaluation/`) | Run `model_comparison.ipynb` after the models are trained. It writes the comparison table and plots to `results/comparison/`. |
| **Decode routes with the HMM** (`hmm_viterbi/`) | Run `hmm_viterbi.ipynb`. It tunes the HMM, compares it with the classifier alone and writes `results/hmm/` including the route maps. To use the decoder from code: `from pathsnap_hmm import TripNet, prepare_trip, viterbi_trip, reconstruct_route`. |
| **Predict one trip from code** (`api/predict.py`) | `python api/predict.py "<path to a trip folder>"` runs the whole pipeline on one raw trip. In Python: `from predict import match_trip`. |
| **Serve predictions** (`api/api.py`) | See "Run the API and UI". Endpoints: `GET /health`, `GET /trips`, `POST /predict {"trip_id": "..."}`. Interactive docs are at `http://<laptop 1 IP>:8000/docs`. |
| **Show results to evaluators** (`ui/`) | See "Run the API and UI". |
| **Draw a trip** (`visualisations/`) | `python visualisations/visualize_trip.py <trip id> --out trip.png` for a plot, or add `--html map.html` for a Folium map. `figures.py`, `concept_figures.py` and `cleaning_figure.py` make the report figures (usage is in each file's header). |
| **Look at saved results** (`results/`) | Each model folder has `results.json` (metrics), `cv_folds.csv`, per-trip scores and figures. `results/final_model/` is what the API loads: `classifier.joblib`, `classifier_config.json`, `hmm_config.json`. |

## Notes

- Models and results in `results/` are small enough to commit (about 24 MB in total).
- No credentials or keys are used or stored anywhere in the repository.
- Models are fitted on the 80 training trips only. The 10 `student_test` trips are the held-out trips the API serves
  and the results above are measured on.
